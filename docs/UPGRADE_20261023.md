# 双实例播放与下载修复（2026-10-23）

本轮基于 `ac5eee7` 融合已有的多账号、扫码/API 双登录、Nebula UI、faststart 和 480P 功能。具体发布提交以 `git log -1` 及运维记录为准；真实账号不退出、不删除，原管理员密码、查看密码、API 凭据与加密密钥不变。

## 行为变化

- 修复上一提交的 UTF-8 编码损坏，恢复首页中文、输入框和 HTML 标签；沿用深色侧栏、媒体卡片、手机底部导航及播放器浮层修复。
- 已有流畅版时默认播放 480P，菜单中仍可明确选择原画。浏览器报告的 `4g` 不能代表到服务器的实际吞吐。切画质保持当前进度与倍速，关闭播放器清理轮询、事件和视频连接。
- 新流畅版使用 H.264/AAC、YUV420P，关键帧间隔上限 48 帧，不放大小视频；限制编码线程为 2。已有流畅版继续保留，不为升级强制重转。
- 原画缓冲超过 3 秒且流畅版可用时自动降级。索引优化不能补足线路带宽，原画码率高于实际吞吐时仍会缓冲。
- 原画及流畅版直接使用浏览器附件下载，支持 Range 续传；选中媒体流式生成 ZIP64，不复制整个视频到浏览器内存或服务器临时目录。ZIP 支持大于 2/4 GiB 的单个文件；ZIP 打包流本身不支持断点续传，长任务建议逐个下载。
- 修复取消扫码后迟到响应重新显示二维码的竞态，异步结果绑定账号及本次操作；保留 API 凭据复用与双登录入口。
- FFmpeg 的输出和错误同时消费，避免错误管道满后卡死；服务停止/超时会结束并回收子进程。索引重封装增加剩余空间检查，失败保留原文件；取消后可重新排队。优化过程中暂时禁止删除或重命名正在处理的视频，批量删除先完整检查再执行。

`tests/accounts_ui.mjs` 在无头 Chromium 中通过：独立测试账号的扫码/两步验证、手机号/API/验证码/两步验证、重命名、取消结束会话、网络失败保留会话并重试、只移除目标测试账号、刷新恢复，以及 320/390 像素布局。测试服务强制使用临时数据和模拟 Telegram；不挂载生产数据、不向真实账号发送验证码、不退出生产账号。

## 更新与回滚

VPS 先检查工作树干净并备份，保留正在运行的镜像 ID，然后：

```bash
cd /opt/telegram-video-manager
git fetch origin
git merge --ff-only origin/main
docker compose build app
docker compose up -d --no-deps --force-recreate app
# 应用地址可能变化，重启本项目 Nginx 以刷新 Docker DNS。
docker compose restart nginx
docker compose ps
curl -fsS http://127.0.0.1:8080/health
```

不运行首次安装/初始化脚本，不改 `.env`，不删除 Session 或卷。InstaBox 按 [专用运维说明](INSTABOX.md) 执行 `bash scripts/instabox.sh deploy`，使用独立 8081 和 Compose 项目。Akile、Komari、1Panel 和外部保活服务不属于更新对象。

本轮没有新增数据库结构变更。VPS 可将备份 `image` 文件记录的旧镜像重新标记为 `telegram-video-manager-app`，以 `docker compose up -d --no-build --force-recreate app` 回退，再重启本项目 Nginx；持续回退还要在干净工作树切回备份 `commit` 对应代码。InstaBox 可用旧 `IMAGE_TAG=7ba4f2ce9e94` 按专用说明回退。均先备份当前数据；不以旧快照覆盖较新的会话和媒体，除非确需配套数据恢复。

## 依据与边界

MP4 索引前置依据 [Nginx 的 MP4 索引说明](https://nginx.org/en/docs/http/ngx_http_mp4_module.html) 和 [FFmpeg 的 faststart 文档](https://ffmpeg.org/ffmpeg-formats.html#mov_002c-mp4_002c-ismv)。播放仍使用浏览器原生视频能力，不引入外部 CDN 脚本。

真实扫码和验证码登录需要用户手机确认，本轮保留现有授权；模拟成功不能作为新增真实账号登录成功的证据。手机验收使用移动尺寸 Chromium，不等同于真机 Safari。完整真实大视频下载、线路长期稳定性及未下载媒体的转码耗时仍需持续观察。
