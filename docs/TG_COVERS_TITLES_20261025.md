# Telegram 原封面与清晰标题

频道、服务器媒体库、视频收藏和播放器改为优先展示 Telegram 原消息的说明标题；文件名保留作次要信息。“展开 TG 说明与完整文件名”可查看完整原文，不再只能依赖两行截断的文件名。标题字号、字重和行距提高，明暗主题都使用正文高对比颜色；卡片最多显示 3–4 行，播放器标题最多 2 行，完整原文仍在展开区域。

展示标题取消息说明中第一个有文字/数字、且非纯链接或用户名的有效行，无说明时用原文件名。说明作为纯文本转义显示，换行保留。不会改名、改路径或改变另存附件的原文件名。媒体库和收藏搜索支持说明中的关键词，播放列表也支持按展示标题搜索；选集排序仍遵循既有文件名/当前列表顺序。

## 封面优先级

1. 原 Telegram 消息的自定义 `video_cover` 图片。
2. 视频文档中的最大静态缩略图。
3. 来源没有图片、已删除/不可访问或读取失败时，回退到已下载视频的本地抽帧图。

旧逻辑会直接使用已下载视频的抽帧图，导致原 TG 封面被遮盖。现在频道和媒体库共用账号隔离的封面服务。明确指定静态 PhotoSize 类型，避免 `thumb=-1` 取到动画 MP4 并将其误作 JPEG。图片经格式校验、临时文件原子替换后缓存，不重新下载完整视频，不裁切原封面。实现依据 [Telegram 自定义视频封面字段](https://core.telegram.org/constructor/messageMediaDocument) 和当前安装的 Telethon 1.45.0 下载实现。

新封面缓存为 `thumbnails/telegram/source-v2/<账号>/<频道>/<消息>.jpg`；旁边 `.source` 标注 `telegram-custom` 或 `telegram-thumbnail`。旧抽帧图和旧缓存保留，可用于回退、回滚。前端 URL 增加 `v=2`，避免浏览器继续复用旧抽帧图片。响应头 `X-Thumbnail-Source` 便于判断实际来源；TG 图片缓存 1 小时，本地回退图缓存 60 秒，防止一次网络故障让抽帧图长期盖住原封面。

同一来源并发请求合并、每账号最多 3 路封面读取；有抽帧回退时 TG 读取限时 8 秒，失败后 45 秒内复用回退；无回退时读取限时 20 秒并支持手动重试。消息本身完全没有静态图片时，挑选页显示无封面占位，不凭空补造封面。`video_cover` 与视频缩略图都不代表相邻文字消息中的独立图片，后者不猜测绑定到视频。
