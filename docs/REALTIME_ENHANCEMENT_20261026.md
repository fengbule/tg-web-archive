# 实时增强 2.0：修复效果过弱与手机缩放问题

播放器“增强”现支持自然 35%、清晰 70%、较强 100%，也可用强度滑块自行调整。建议从清晰档试起。点击底部“左右对比”可在同一帧上查看左原画、右增强；不必打开设置挡住画面。设置中可调整分界线，按住原画仍可临时比较。当前浏览器记住增强模式和自定义强度，对比分屏只在本次播放器中生效。

从媒体菜单打开“实时增强”时，未启用增强的浏览器默认使用清晰档；已有模式/自定义强度则保留，不再每次强制重置成自然档。

旧版的五点高通、较高的噪声门限与小幅增量限制，叠加手机缩放后容易难以察觉。旧测试只证明像素变化，不能证明有足够的可见改善。此次改用基于 [AMD FidelityFX CAS](https://gpuopen.com/fidelityfx-cas/) 思路适配的亮度自适应锐化，结合较宽范围的局部对比度；在近似线性亮度中计算自适应权重，再限制最终亮度增量，不简单拉高亮度或饱和度。来源和 MIT 许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)，许可也随浏览器脚本分发。

输出画布适应显示区域和设备像素比（最高 2），采样半径同时考虑视频与显示像素，避免先微弱锐化、再缩放将效果抹掉。画布有 4096 边长/约 4 百万像素预算以限制客户端开销；不改变原文件或下载的分辨率，也不声称恢复源视频里丢失的细节。较强档可能同时放大压缩块、颗粒和边缘光晕，可调低或关闭。

仍使用唯一视频元素和原音轨，增强没有独立播放时钟；拖动、选集、后台暂停处理、无 WebGL/资源丢失/超负荷恢复原画等行为保留。系统视频全屏/画中画不支持叠加画布时，状态与工具键明确显示原画，网页全屏继续增强。关闭或浏览器退回原画时不会假装仍在增强。

## 验证与效果边界

新增 `tests/realtime_quality_ui.mjs` 用柔化的细纹、斜线、文字及可选的公共领域 NASA 参考图，比较旧/新算法在实际显示尺寸下的边缘对比度、变化幅度及分屏原画侧。它检验可见的软细节变化，不把 SSIM 或像素差当成画质评分。测试图片只留在独立测试目录，不含用户素材、不提交二进制样片。

390 宽测试中，新旧平均变化分别约 4.87/1.43（0–255 通道尺度），细纹边缘对比度相对原画增加约 85%/15%；1280 宽增加约 27%/1%。这些数值只描述这组测试图与显示尺寸，不能外推为所有视频“清晰度提高多少倍”。真实影片还需结合自身压缩程度判断；模糊、失焦、低码率造成的信息缺失仍在。

还在 VPS 三条已有影片的同一暂停帧上读取 GPU 像素，包含 1920×1080、1280×720、854×480 源，在约 390 宽显示区测得旧/清晰档平均变化约 0.19/2.54、0.26/1.93、0.34/1.70；较强档约 4.34、3.48、3.20。仅保存数值，无真实视频帧或封面导出/提交。这证明实际播放素材上的处理幅度已提高，不证明所有画质失真都减少。

7 组无头浏览器检查通过：显示尺寸下的清晰度对比、实时增强控件、离线增强、原画拖动、控件交互、开启增强后的锁屏/选集、TG 相册封面。覆盖强度滑块、自定义强度/快捷入口偏好、同帧分屏原画侧、连续跳转、唯一音视频时钟、GL 丢失恢复、无 WebGL、旧帧回调、320/390/1440 明暗主题；没有生成额外服务器增强任务。
